* Our Shell Grammar

user-input  ::= list

list        ::= conjunction
              | conjunction LIST-SYMB list

conjunction ::= disjunction
              | disjunction AND-SYMB conjunction

disjunction ::= pipeline
              | pipeline OR-SYMB disjunction

pipeline    ::= command
              | command PIPE-SYMB pipeline

command     ::= word
              | word SPACE-SYMB command

LIST-SYMB  ::= ';'
AND-SYMB   ::= '&&'
OR-SYMB    ::= '||'
PIPE-SYMB  ::= '|'
SPACE-SYMB ::= ' '

* Processing Input

- Process each line one by one.
- Tokenize the line by whitespace.
- Collect the tokens into an array of strings.
- If first token matches a "built-in" function, execute it.
- Otherwise, process it as a "list".

[[file:../src/lugshell.c::264]]


* Lists

list        ::= conjunction
              | conjunction LIST-SYMB list

- List: collection of "conjunctions".
- Separated by ';' tokens.
- Execute each conjunction one-by-one.
- Result code is result of last conjunction in the list.

[[file:../src/lugshell.c::237]]


* Conjnuctions

conjunction ::= disjunction
              | disjunction AND-SYMB conjunction

- Conjunction: a collection of "disjunctions" AND-ed together.
- Logically D1 && D2 && ... && DN
- Result code is true (zero) only if all D1 ... DN result codes are true.
- False otherwise.

[[file:../src/lugshell.c::208]]


* Disjunctions

disjunction ::= pipeline
              | pipeline OR-SYMB disjunction

- Disjunction: a collection of "pipelines" OR-ed together.
- Logically P1 || P2 || ... || PN
- Result code is true (zero) if at least one of P1 ... PN result code is true.
- False only if all P1 ... PN are false.

[[file:../src/lugshell.c::175]]


* Pipelines

pipeline    ::= command
              | command PIPE-SYMB pipeline

- Where the fun starts!
- Pipeline: a collection of "commands" separated by a pipe-operator.
- C1 | C2 -- C1's output is connected to C2's input.
- Allows for complex commands to be constructed from simpler pieces.
- The core of the Unix Philosophy.

[[file:../src/lugshell.c::144]]


* One Child Per Command

- fork() system call creates a clone of the running process.
- exec() family of calls replaces current process with another.
- Child process inherits some things from the parent process.
- e.g. file descriptors.
- wait() family of calls to wait for the child to complete.

[[file:../src/lugshell.c::103]]


* Connecting The Outputs

- pipe() and dup2()
- C1 | C2
- Idea: create an unnamed pipe.
- Replace C1's stdout with the pipe's input side.
- Replace C2's stdin with the pipe's output side.
- C2 reads in what C1 writes out.

* Signals

- One method of sending a message to another process.
- See the kill command.
- Processes register "signal handlers".
- Upon receipt, process jumps to signal handler, resumes
  execution there.
- Very non-local program flow.
- Very dangerous.


* Handling SIGINT

- When user hits Ctrl-C, we want to handle it gracefully.
- Terminate current line of input. Prompt user.
- Just jump back to our read/eval loop.
- setjmp(): sets up a "continuation" of sorts.
- longjmp(): jump back to the continuation registered via setjmp().
- BUT: not signal-safe.
- Need POSIX functions: sigsetjmp() and siglongjmp()
